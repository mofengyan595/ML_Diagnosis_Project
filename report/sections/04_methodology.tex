\section{方法与实验设置}

\subsection{整体流程}

本文采用统一流程完成模型比较：
原始数据先经过缺失值处理、异常值裁剪、标准化和分层划分，
随后在相同训练集、验证集和测试集上训练并评估不同模型。
验证集用于模型选择和超参数调优，
测试集仅用于最终性能报告。
图 \ref{fig:system_pipeline} 展示了离线实验流程与在线问诊系统推理流程之间的关系。

整体流程可以概括为
Dataset $\rightarrow$ Preprocessing $\rightarrow$
Train/Validation/Test Split $\rightarrow$ Model Training/Tuning
$\rightarrow$ Evaluation $\rightarrow$ System Demonstration。
其中，预处理阶段与第 \ref{tab:iqr_bounds} 表所述方法保持一致：
先将不合理 0 值标记为缺失，再仅基于训练集拟合中位数填充器、
IQR 裁剪边界和标准化器。
这些预处理参数在训练完成后被保存为独立对象，
并在验证、测试和系统预测阶段重复使用。
因此，系统端接收到的单条用户输入不会直接进入分类模型，
而是先按照训练阶段相同的特征顺序和变换规则完成清洗、裁剪与标准化。
该设计能够保证模型训练阶段与系统应用阶段的数据处理逻辑一致，
减少由于人工输入原始指标而带来的分布偏移。

在系统展示阶段，本文将实验阶段选定的分类模型与上述预处理对象共同封装。
系统界面只负责收集用户输入并展示预测结果，
核心预测逻辑由独立的预测模块完成：
首先根据 8 个特征构造单样本输入表，
随后调用保存的预处理对象完成数据变换，
最后由训练好的分类模型输出阳性概率。
这种模块化设计将数据处理、模型训练和交互展示解耦，
既便于复现实验流程，也便于在模型更新后保持系统界面和推理接口稳定。

\subsection{模型选择}

本文首先使用 Logistic Regression 作为可解释基准模型：
设置 \texttt{class\_weight="balanced"}、最大迭代次数 1000、
随机种子 42，并将其作为后续模型比较的参照。
在此基础上，多模型比较阶段使用预处理后固定划分的训练集、
验证集和测试集，不再重复清洗或重新划分数据。
所有候选模型均只在训练集上拟合，
并分别在验证集和测试集上使用相同指标进行评估，
从而保证不同模型之间以及与 Logistic Regression 基准模型之间的公平可比性。

除 Logistic Regression 基准模型外，实验共纳入 7 个候选模型。
KNN 根据邻近样本的距离和投票结果进行分类；
Decision Tree 基于特征阈值递归划分样本空间；
Random Forest 通过 Bagging 方式集成多棵决策树，以降低单树模型的方差；
SVM 通过最大化分类间隔寻找决策边界；
Gradient Boosting、XGBoost 和 LightGBM 均属于 Boosting 集成方法，
通过逐步拟合前一阶段的误差提升分类性能。

本文采用统一协议计算 Accuracy、Precision、Recall、F1-score 和 ROC AUC。
由于糖尿病风险预测属于筛查任务，
漏判高风险样本可能使潜在阳性个体错过进一步检查，
因此模型比较不能只关注 Accuracy，
还应重点观察 Recall 和 F1-score，
并结合 ROC AUC 衡量模型对正负样本的整体排序能力。

\subsection{超参数调优协议}

多模型阶段应使用验证集或交叉验证进行超参数选择。
若采用 GridSearchCV 或 RandomizedSearchCV，
需要报告搜索范围、交叉验证折数、选择指标和最优参数。
对于糖尿病筛查任务，调参时不宜只优化 Accuracy，

\subsection{评价指标}

糖尿病预测是类别不平衡二分类问题，
单一 Accuracy 可能掩盖阳性样本漏判。
因此本文纳入了 Accuracy、Precision、Recall、F1-score 和 ROC AUC作为评价指标。
其中 Recall 衡量真实阳性样本被正确识别的比例；
在筛查场景中，假阴性意味着潜在高风险个体被漏掉，
因此 Recall 和 F1-score 比单纯 Accuracy 更需要关注。
ROC AUC 不依赖单一分类阈值，
用于衡量模型对阳性样本的概率排序能力。
